Agentforceでナレッジが
見つからないときの切り分け手順。

Knowledge記事は公開済みなのに、Service Agentが「情報が見つかりません」と答える。すぐにプロンプトを増やす前に、検索対象 → 索引 → アクション → 権限 → 質問表現を分けて確認します。

本記事はSalesforce公式資料に基づく一般的な調査手順です。特定顧客の障害報告や修復実績ではありません。AgentforceのUI、機能、ライセンス条件は組織・リリースによって異なるため、利用環境の公式ドキュメントを優先してください。

最初に「どこで失敗したか」を分ける

同じ「回答できない」でも原因は別です。①Data Library自体が割り当てられていない、②検索対象に記事が入っていない、③検索結果はあるが回答に反映されない、④言い換えた質問だけ見つからない、の4パターンに分けます。エージェント全体の回答だけで判断せず、可能なら該当アクションを単独でテストしてください。

1. Knowledgeの公開状態と検索対象フィールドを確認

対象記事の公開状態・言語・データカテゴリ・公開チャネルを確認し、Data Library側のKnowledgeソース、検索対象の本文フィールド、公開記事への制限、カテゴリ絞り込みと突き合わせます。本文がカスタム項目にある場合、対象フィールドの選択漏れも候補です。SalesforceのKnowledge Library例では、索引対象のテキスト項目とデータカテゴリの指定が説明されています。

公開サイト向けエージェントで社内専用記事を参照できるように権限を広げるのは解決策にしません。まず必要な記事だけが公開範囲に含まれるか確認します。

2. Data Libraryの「作成済み」と「検索可能」を区別

ライブラリの存在だけでは索引・Retrieverが使えるとは限りません。検索インデックスやRetrieverの準備状況とエラーを確認します。Salesforce CLIを利用できる管理環境なら、sf agent adl status --library-id <ライブラリID> --target-org <組織エイリアス> でDATA_STREAM、SEARCH_INDEX、RETRIEVERなどの段階を確認できます。組織やCLIの対応バージョンを確認して実行してください。

索引が未完了・エラーの場合は、失敗段階と公式エラー情報を記録してから対処します。むやみにライブラリを削除・再作成すると、調査の手掛かりや設定を失う可能性があります。

3. エージェントへの割り当てとKnowledgeアクションを確認

Agentforce Builderで、対象エージェントと有効なバージョンに正しいData Libraryが割り当てられているか確認します。次に、使用するサブエージェント（またはトピック）とAnswer Questions with Knowledgeなどのアクションが実際に呼び出されるかを確認します。独自Prompt TemplateやRetrieverを使う構成なら、アクションの参照先が想定と一致するかも見ます。

「アクション単体では記事が返るが、会話では使われない」場合、検索基盤を作り直す前にアクション選択条件・指示・後段の応答加工を切り分けます。根拠のない回答を強制する指示は追加しません。

4. エージェント実行ユーザーの権限を確認

管理者として記事が見えても、エージェント実行時に同じ範囲へアクセスできるとは限りません。Knowledgeへのアクセス、必要な権限セット、Data 360側のアクセス範囲を、実行主体に沿って確認します。権限を一律に管理者相当へ上げず、最小権限で再テストします。

5. 質問の言い方と記事の用語がずれていないか確認

製品の旧称、略語、社内用語、利用者の俗称と、記事に書かれた正式名称が異なると、関連箇所を検索できない場合があります。Salesforce公式のAgent Script例も、この用語のずれを検索失敗の一因として扱っています。まず「記事の見出しそのまま」と「利用者の自然な言い方」の両方でテストし、差が出るか記録します。

必要なら公開範囲を守りながら用語の対応表や記事の見出しを整えます。回答できない質問に対して、根拠を作り出すのではなく有人窓口などの安全な案内を残します。
