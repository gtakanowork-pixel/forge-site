Enhanced Web Chatで
事前入力が反映されないとき。

SalesforceのWebチャットで事前入力した値が表示されない。コードを何度も書き換える前に、対象製品・フィールド設定・初期化イベント・会話開始の順番を分けて確認します。

本記事はSalesforce公式開発者資料をもとにした一般的な検証手順です。特定企業の導入事例・障害実績ではありません。組織のリリース、チャネル構成、権限によって利用可能な設定は異なります。

1. まず「Enhanced Web Chat」か確認する

古いEmbedded Service Chatのコード例にある embedded_svc.settings.prepopulatedPrechatFields と、Enhanced Web Chatの embeddedservice_bootstrap.prechatAPI は別の仕組みです。検索結果に出てきた旧製品のサンプルをそのまま貼り付けず、導入済みチャネルとSalesforceが発行した埋め込みスニペットを確認してください。

2. visible と hidden を混同しない

Visible pre-chatは利用者に表示する事前入力欄です。対象の欄を事前にフォームへ追加したうえで、setVisiblePrechatFields を呼びます。Hidden pre-chatはフォームに表示しない情報を渡す別経路で、setHiddenPrechatFields を使います。表示されないことだけで「送信されていない」とは断定できません。どちらを設計したのかを先に整理します。

3. フィールド名は画面のラベルではなくチャネル変数名

VisibleのキーはSalesforceのMessaging Settings → 対象チャネル → Parameter Mappingsにあるチャネル変数名を使います。標準の例は _firstName、_lastName、_email、_subject です。独自項目は組織で設定した変数名を確認してください。画面の「件名」などの表示ラベルをキーとして指定しても一致しません。

4. APIは ready イベント後、会話開始前に呼ぶ

onEmbeddedMessagingReady はAPIが使用可能になった合図です。Salesforce公式手順では、このイベントの後、会話が始まる前にpre-chat APIを呼びます。イベントの登録自体はSalesforce提供スニペットの初期化より前に行い、利用者の入力値を勝手に固定しないよう、編集可能な設定から試してください。

次は架空の件名だけを設定する最小例です。実際には、対象チャネルのVisible pre-chatに _subject があることを先に確認してください。既存のSalesforceスニペット全体を置き換えるコードではありません。

window.addEventListener('onEmbeddedMessagingReady', () => {
  window.embeddedservice_bootstrap.prechatAPI
    .setVisiblePrechatFields({
      _subject: {
        value: '動作確認',
        isEditableByEndUser: true
      }
    });
});
// このリスナーを登録してから、Salesforce提供スニペットで初期化する

画面に反映されない場合は、イベントが発火したか、prechatAPI が存在するか、変数名が一致するか、対象フォームに欄があるかを順に確認します。設定後に既に会話が開始していないかも切り分けます。

5. 値の変更・削除も開始前にテストする

Visibleの事前入力を解除するには unsetVisiblePrechatFields、Hiddenを解除するには removeHiddenPrechatFields を使います。ログアウト、別ユーザーへの切替、再訪問などで前の利用者の値を残さない設計が必要です。認証済みユーザーのセッション継続・本人確認は別の仕様なので、単なる事前入力を本人確認の代わりに使わないでください。

架空データだけで行う5つの確認

  1. 公式スニペットで、事前入力なしのチャットが正常に開く。
  2. onEmbeddedMessagingReady の発火を確認する。
  3. フォームに設定したVisible項目とチャネル変数名が一致する。
  4. 架空の件名を設定し、会話開始前のフォームに反映される。
  5. 値の削除・再初期化を試し、前回の値が意図せず残らない。

検証時は顧客名、実メールアドレス、アクセストークン、チャット履歴をログやスクリーンショットに含めず、架空データで再現してください。環境ごとの正式な権限・セキュリティ設定はSalesforce管理者と確認します。
